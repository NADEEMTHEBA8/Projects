## Decoupling Transaction Storage from Real-Time Model Inference

High-throughput financial fraud detection requires serving complex aggregated features (e.g. 1-hour transaction counts, 24-hour average spend, geographical velocity) to model scoring endpoints with sub-10ms latencies.

Directly querying relational databases during online transaction evaluation creates severe locks and bottleneck latencies. In this architecture, we decoupled event storage from feature serving using **Debezium Change Data Capture (CDC)**, **Apache Kafka (KRaft mode)**, **PySpark Structured Streaming**, and **Redis 7.0**.

## Non-Transactional Pipelined Redis Writes

To achieve high-performance Redis updates across Spark stream partitions, we utilize non-transactional pipelined batch writes to eliminate individual network round-trips:

```python
import redis

def write_features_to_redis(partition_iterator, redis_host: str, redis_port: int):
    r = redis.Redis(host=redis_host, port=redis_port, socket_connect_timeout=1)
    pipe = r.pipeline(transaction=False)
    
    for record in partition_iterator:
        user_key = f"user:features:{record['user_id']}"
        pipe.hset(
            user_key,
            mapping={
                "tx_count_1h": record["tx_count_1h"],
                "avg_amount_24h": record["avg_amount_24h"],
                "last_updated": record["event_timestamp"],
            }
        )
        pipe.expire(user_key, 86400) # 24h TTL to optimize memory footprint
        
    pipe.execute()
```

## Key Metrics & Performance Achievements

- **Sub-10ms P99 Latency**: FastAPI scoring endpoints retrieve complete 24-hour feature vectors from Redis in under 8 milliseconds.
- **Dead Letter Queue (DLQ) Resilience**: Malformed JSON payloads are routed automatically to `transactions.dead_letter` Kafka topics without interrupting active PySpark streams.
- **Automated PII Masking**: Sensitive fields (`device_id`, `ip_address`) are deterministically hashed via SHA-256 before landing in MinIO Delta Lake 3.0 storage.
